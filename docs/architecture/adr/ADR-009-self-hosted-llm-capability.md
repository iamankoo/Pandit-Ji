# ADR-009: The self-hosted LLM capability (`services/agent`, package `pandit_agent.llm`)

Status: Implemented 2026-10-03 (Phase 14), within existing owner decisions (ADR-002, ADR-003, `TECH_STACK.md`). It adds no canonical service. It is recorded for owner review because it fixes where Phase 14 code lives and which model and runtime were selected.

## Context
ADR-002 requires self-hosted inference behind an `LLMProvider` / AI Reasoner interface and defers the model, the fine-tuning and the serving stack to Phase 14. `docs/ARCHITECTURE.md` §16 puts a dedicated inference *process* behind that interface and says the agent never embeds the model in-process; §27 locks the service structure and assigns "LLM orchestration" to `agent`. `Phases.md` Phase 14 asks for a self-hosted inference service and lists no new directory. The Phase 14 instruction says to use the existing canonical location and not to create a new top-level service unnecessarily.

## Decision
1. **Location.** The LLM capability lives in the existing canonical service `agent`, as the subpackage `pandit_agent.llm` (like `voice/` and `reports/`), with its data assets (manifests, the pinned chat template) in `services/agent/llm/`. The typed contracts live in `packages/contracts` (`pandit_contracts.llm`). No sixth or seventh canonical service is created.
2. **Process boundary.** The *inference engine* is not in the agent: it is a separate self-hosted vLLM server process. `pandit_agent.llm` contains the interface (`LLMProvider`), the service that assembles the prompt, validates output and reports health, and a thin HTTP runtime that talks to that server. This preserves §16 ("the agent never embeds the model in-process").
3. **What the package is not.** It has no planner, memory, tool selection, narration or verification. It receives a fully specified request and returns a response; Phase 15 sits on the other side of the interface. A test asserts the package imports no other service and that no other package imports the agent.
4. **Model and runtime.** `Qwen/Qwen3-8B` at revision `b968826d9c46dd6066d109eabc6255188de91218` served by vLLM (the model card asks for 0.8.5 or later; 0.19.1 was the latest on the package index on 2026-10-03 and was not run). Evidence and the other candidates read: `research/AI_MODELS.md`. The basis is verified fit to the recorded requirements (licence text read, ungated, hashes, Hindi listed, chat template, runtime compatibility), not a quality ranking: none was measured.
5. **Self-hosted only.** No client for a hosted third-party model API exists. The HTTP runtime refuses any host not on an operator allow-list (default loopback), follows no redirects, ignores proxy settings and never echoes a response body. There is no fallback runtime and no silent model switch: a request for a model that is not the loaded one fails.
6. **Weights.** Never in git. A manifest pins the revision and a SHA-256 for every artifact; acquisition is an explicit operator step; the loader verifies a configured model directory against the manifest. CI uses a scripted test runtime that is labelled as such in every response.
7. **Hard boundaries are structural.** The caller cannot send a system message (the system block is assembled from fixed, versioned text plus the typed context); restricted categories travel as typed values (the Phase 13 `ProhibitedCategory` vocabulary) and the generated text is also scanned against the same closed lexicon; structured output is parsed strictly and validated against a registered schema after generation. A prompt instruction alone is never the control.

## Options considered
- **A new `services/llm` or `services/inference`.** Rejected: the locked structure and canonical names would need an owner decision (as ADR-008 did for palm-vision), and ARCHITECTURE already names the agent's `LLMProvider` as the consumer. The cost of the chosen option is that Phase 14 code sits in the Phase 15 service; the boundary is held by the subpackage, the tests and this ADR. If the owner prefers a separate component, the package moves with no interface change.
- **Embedding Transformers in-process.** Rejected: contradicts §16 and ties the agent's process to GPU memory. Transformers is used only to validate the tokenizer against the pinned template in an optional local test.
- **A hosted stopgap for development.** ADR-002 allowed one; Phase 14 does not implement it, so no user content can reach a third party. The development tier of `TECH_STACK.md` (Ollama) is **not implemented**: the same vLLM runtime runs on a developer GPU and CI uses the scripted runtime. Recorded as a gap, not hidden.

## Consequences
- `docs/ARCHITECTURE.md` §16 is amended and a new §36 records the design and limits; `TECH_STACK.md` records the checkpoint and runtime; `LEGAL_REGULATIONS.md` records the licence reading (not legal approval); `research/AI_MODELS.md` records the evidence.
- Status vocabulary: IMPLEMENTED (contracts, manifest, loader, template handling, context assembly, structured output, policy scan, health, errors, observability, mock runtime, vLLM HTTP runtime against a protocol fake); MODEL_DOWNLOAD_REQUIRED and HARDWARE_REQUIRED (the real model has not been downloaded or served); OPTIONAL_LOCAL_TEST (a real server and a tokenizer cross-check, skipped in CI); CALIBRATION_REQUIRED (language quality, structured-output reliability, latency, tolerances); LEGAL_REVIEW_REQUIRED (licence, prohibited-output coverage for Hindi and Hinglish); FUTURE_PHASE (planner, narration, tools, verification, fine-tuning).
- Phases 6 to 13 are unchanged: the agent depends on `packages/contracts` and `packages/shared` only, and reads the Phase 13 `PalmEvidenceBundle` through its public contract.
