# ADR-010: Agent orchestration and narration (`services/agent`, package `pandit_agent.orchestration`)

Status: Implemented 2026-10-03 (Phase 15), within existing owner decisions (ADR-002, ADR-003, ADR-009, `Phases.md` Phase 15). It adds no canonical service. It raised four decisions for the owner, which were locked on 2026-10-03 (see "Owner decisions locked" at the end).

## Context
`Phases.md` Phase 15 asks for intent detection, planning, tool selection, tool execution, context management, memory, multi-step reasoning and error recovery. `docs/ARCHITECTURE.md` section 8 gives the flow and section 16 the inference boundary; ADR-003 puts the agent in `services/agent`; ADR-009 provides `LLMProvider` and the self-hosted model. Phase 16 owns verification; Phase 18 owns upload, storage, consent, retention and the database API. The Phase 15 instruction asks for bounded planning, structured narration with references Phase 16 can check, preserved provenance and uncertainty, domain separation, and no hosted model.

## Decisions
1. **Location.** `pandit_agent.orchestration` inside the existing `agent` service, next to `llm`, `voice` and `reports`. No new component. The package imports the Phase 14 provider interface only (a test forbids importing the runtime, loader, manifest or service), the foundation packages and pydantic.
2. **Bounded, deterministic planner; closed tool allow-list.** Intent classification is a keyword classifier and the plan is a static preset, so the plan is reproducible and cannot be steered by user text or the model. Tools are `EvidenceTool` objects in a registry; a tool takes no free-form arguments (only the capability set the plan requested), has a timeout and a call budget, and contains its own failures. The agent computes no fact: tools hand over bundles that deterministic components already produced. This reading of "tool selection" (selection among allow-listed deterministic evidence tools, not model-chosen function calls) is the smallest one that satisfies the roadmap and the safety brief.
3. **Memory scope.** Only in-session conversation context, as labels. Persistent long-term memory is Phase 18 (user-scoped storage, consent, retention, deletion; ARCHITECTURE section 17). `Phases.md` lists "Memory" in Phase 15, so this is a **partial** implementation by design, recorded in the status block.
4. **Referential grounding in Phase 15, semantic verification in Phase 16.** The agent rejects a narration whose claims cite ids that are not in its own context, whose claim type does not match the semantic class of the evidence it cites (a derived fact is never "observed"), whose interpretation rests on a rule that is not `TRIGGERED`, that merges conflicting source profiles, or that claims to be verified. It does **not** judge whether a claim's text follows from its evidence: that is verification. The instruction says Phase 15 need not verify that referenced ids are valid; checking them against the agent's own context is a trust-boundary guard (a model cannot invent an id that later looks like provenance), not a replacement for Phase 16. **Locked by the owner on 2026-10-03 as the permanent Phase 15 / Phase 16 boundary.**
5. **Domain policy scoping.** `PRODUCT_POLICIES.md` allows contextual, traditional interpretation of high-impact astrology topics (health, finance, legal, relationships, pregnancy, death) with a professional-advice disclaimer, prohibits lifespan outputs (the Ayurdaya exclusion, standards P9-06/P9-10) and prohibits fear-based framing; Phase 13 permanently prohibits a longer list for palmistry (PM-13, PM-25). The Phase 15 instruction lists the palmistry prohibitions for the agent. The agent therefore applies the full list to the PALMISTRY domain and, for ASTROLOGY, refuses lifespan and death-timing requests and restricts lifespan in output, adding the professional-advice disclaimer for high-impact topics. Applying the palmistry list to astrology would contradict the existing high-impact-topics policy; applying only lifespan to palmistry would contradict PM-25. **Locked by the owner on 2026-10-03.**

Also recorded: the additive `LLMContext.task` field in `packages/contracts` (a trusted task instruction channel, because Phase 14 deliberately accepts no system message from callers). It is optional and absent from the request hash when unset, so every Phase 14 hash and test is unchanged.

## External guidance considered
OWASP GenAI Security Project, LLM01 Prompt Injection (read 2026-10-03): constrain model behaviour; define and validate output formats; input and output filtering; least privilege; segregate and identify untrusted content; adversarial testing; and its statement that fool-proof prevention is unclear. The design adopts these structurally (typed channels, schema-constrained and validated output, no model tool access, no-argument tools, adversarial tests) and does not claim prevention. No dependency was added on the strength of this guidance.

## Consequences
- Phase 16 receives `NarrationResponse.claims` with structured references and `UNVERIFIED` state. Verification (extracting and checking claims against the bundle) is not built.
- `docs/ARCHITECTURE.md` section 37 describes the design and its limits; `Phases.md` Phase 15 carries the status block; `SUMMARY.md` section 46 the handoff.
- Not implemented (not hidden): adapters for dasha, transit, compatibility and knowledge-retrieval evidence; combined-domain requests; voice; reports; persistent memory; any real-model run. Every test ran against the scripted Phase 14 runtime.

## Owner decisions locked (2026-10-03, Phase 15 closure)
1. **Domain policy scoping** (item 5): kept as implemented. Palmistry retains the complete Phase 13 list and is never weakened; astrology keeps lifespan and death-timing refusal and the professional-advice disclaimer for high-impact topics; the two lists are not merged and astrology is neither widened nor narrowed. The closure aligned two details with the locked wording (English death-timing phrasings are refused; death is listed among the high-impact disclaimer topics, as `PRODUCT_POLICIES.md` states).
2. **Phase 15 / Phase 16 boundary** (item 4): permanent. Phase 15 = structural provenance and reference integrity and `UNVERIFIED`; Phase 16 = whether claims are supported, and the only phase that may set `VERIFIED` or `verified_by`.
3. **Tool selection** (item 2): static, deterministic, allow-listed; no model-chosen function calling; richer tools in a later phase must extend the architecture explicitly.
4. **Memory** (item 3): in-session only; persistent memory belongs to later infrastructure (Phase 18 Memory API, Phase 20 personal memory).
Status after closure: **Locked.** Not built and deferred, with their assigned phases: dasha, transit, compatibility and knowledge-retrieval evidence tools (Phase 18, which builds those APIs and composes the services; the roadmap does not name the adapters, so this assignment is recorded here); persistent memory (Phase 18, Phase 20); verification (Phase 16). The real model has not been run.
